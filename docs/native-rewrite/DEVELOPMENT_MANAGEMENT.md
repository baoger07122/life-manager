# Home OS 原生开发管理规范

> 本文负责控制范围、阶段、版本、验收和交付。它不能把“页面看起来完成”误记为“功能已发布”。

## 1. 产品与代码边界

1. Web 版是需求与交互的快速验证渠道，继续独立维护。
2. 原生 App 使用 SwiftUI/UIKit 实现，不使用 `WKWebView` 承载正式业务页面。
3. Web 确认后，原生实现保持字段、备份 JSON 和云 API 兼容。
4. 原生测试 Bundle ID 与旧 App 分离，避免覆盖用户现有安装。
5. 未经确认不得重构已确认导航、字体层级、组件或业务流程。
6. Home OS 正式产品环境仅为 iPhone 竖屏；不把 iPad、横屏或分屏列入开发与验收范围。iPad Swift Playgrounds 仅作为预览工程的运行载体。

## 2. 状态定义

| 状态 | 含义 |
| --- | --- |
| 待分析 | 需求存在，但还没有核对 Web 行为、数据和边界 |
| 预览中 | 已在 Playgrounds 展示，使用模拟数据 |
| 预览已确认 | 页面结构、视觉和展示过的基础点击已确认 |
| 正式开发中 | 正在接入真实模型、存储和路由 |
| 构建通过 | 正式代码已经完成编译与自动检查 |
| 待真机验收 | IPA 已产生，需要验证系统能力和真实数据 |
| 已通过 | 用户完成阶段验收 |
| 有问题 | 已登记问题，必须修复并重新验收 |

## 3. 三道交付闸门

### 3.1 Web 闸门

- 明确页面入口、返回目标、空状态、编辑状态和删除结果。
- 明确字段、默认值、单位、排序和统计口径。
- Web 需求仍在快速变化时，不开始完整原生复现。

### 3.2 Playgrounds 闸门

- 使用固定工程 `HomeOSNativePreview.swiftpm` 原位同步，禁止删除整个包后重建。
- 预览只改本地和 iCloud，不提交、不推送、不升级正式版本。
- 用户确认的范围只覆盖实际看到和操作过的内容。
- 临时候选面板在确认后必须从正式页面移除。

### 3.3 正式原生与 IPA 闸门

- 正式代码必须复用 `DesignSystem`，不能在业务页面复制组件样式。
- 编译通过后才能登记“构建通过”。
- 持久化、备份、通知、震动、键盘、iPhone 竖屏安全区、前后台恢复和性能必须由正式构建或真机验证。
- 只有需要发出新 IPA 时才更新版本号、提交、推送并触发 CI。

## 6. 每项需求的固定记录

每项需求必须记录：

- 编号和模块。
- Web 对应版本或页面。
- 用户目标与明确不做的范围。
- 涉及的数据字段、统计口径和兼容风险。
- 复用的 UI 组件编号与交互编号。
- Playgrounds 确认日期。
- 正式实现文件。
- 编译、IPA 和真机验收结果。
- 遗留问题与回滚方案。
